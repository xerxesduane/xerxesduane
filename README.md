# Xerxes Duane, Website

The all-in-one tech studio for small businesses in Dubai.
**Serve first. Build second.**

Vite + React + TypeScript + Tailwind CSS + Framer Motion, prerendered to static
HTML at build time.

## Run locally

```bash
npm install
npm run dev          # http://localhost:5173
```

## Build

```bash
npm run build        # type-check → client build → SSR build → prerender every route
npm run preview      # serve ./dist exactly as production does
npm run lint
```

`npm run build` writes `dist/` with one `index.html` per route, a `404.html`
and a freshly dated `sitemap.xml`. Preview it rather than the dev server when
you want to check prerendered HTML, canonicals or hreflang.

## Deploy

Static site, deploy `/dist` anywhere. `vercel.json` carries the CSP, security
headers and the `/demos → /ai-lab` redirect; `netlify.toml` has an SPA fallback
for Netlify.

## Design system

Light-first, theme-aware. Every colour is a CSS custom property in
`src/index.css` exposed to Tailwind through `tailwind.config.js`, so flipping
`data-theme` on `<html>` re-tints the whole site without a single `dark:`
class:

- **Canvas** warm cream, **cards** white/ivory with thin warm hairlines.
- **Ink** deep navy for headings, muted blue-grey for body text.
- **Accent** two oranges — a bright one for icon tiles and fills
  (`--c-accent`) and a deeper one for accent *text* (`--c-accent-deep`), because
  one orange cannot be both vivid on a tile and AA-legible on cream.
- **Primary buttons** are the deep navy (`--c-navy`), which inverts to a light
  slab in the dark theme.
- **Type** Plus Jakarta Sans throughout (self-hosted variable, latin subset).

A new visitor gets the light theme; an explicitly saved preference always wins.
The pre-paint script in `index.html`, `src/lib/useTheme.ts` and the prerender
all agree on that, so there is no flash of the wrong palette.

Legacy Tailwind colour names (`gold`, `cream`, `ink`, `muted`, `olive`) are
kept and repointed at the new tokens, so older pages moved with the palette
rather than losing their styles.

## Editing content

Almost all copy and data lives in `src/data/`:

| File | What it holds |
| --- | --- |
| `content.ts` | Services, case studies, FAQs, stats, contact details |
| `shell.ts` | Sidebar identity, primary nav (EN + AR), social links |
| `homeBento.ts` | Homepage hero, tool strip, featured projects and results |
| `aiLab.ts` | The AI Lab catalogue — the single source of the tool count |
| `aiLabHome.ts` | Which lab tools the homepage card features |
| `servicePages.ts` / `servicePagesAr.ts` | Service pages, EN and AR |
| `insights.ts` | Articles |
| `workItems.ts` | Generated by `npm run images` — do not edit by hand |

Numbers that change (how many AI tools there are) are derived from their data
source rather than typed in twice.

## The visit counter

The number under the profile is this month's real visit count, or nothing at
all. `api/visits.ts` talks to a Postgres table in Supabase holding one row per
month, keyed in **Asia/Dubai** so the month turns over at midnight in Dubai
rather than 8pm the evening before. Old months are kept, so "resets monthly"
means a new row, not lost history.

It needs two environment variables in Vercel. Without them the endpoint
returns 503 and the rail renders no number — never a zero, never a
placeholder, because an invented visitor count is worse than none:

| Variable | Where to find it |
| --- | --- |
| `SUPABASE_URL` | Supabase → Project Settings → Data API → Project URL |
| `SUPABASE_PUBLISHABLE_KEY` | Supabase → Project Settings → API Keys → publishable (`sb_publishable_…`) |

That key is safe to expose. The table has RLS on with **no policies**, so it
grants no read or write access to the table itself — only `bump_site_visits()`
(adds exactly 1) and `get_site_visits()` (reads). Supabase's linter flags both
as "public can execute a SECURITY DEFINER function"; that is the design, not an
oversight.

A visit is one browser session: the browser sets a `sessionStorage` flag and
tells the server whether to count. Repeat loads, crawlers and anyone hammering
the endpoint all silently fall through to a read instead. Nothing identifying
is sent or stored — no cookie, no IP, no visitor row, one integer per month —
which is why it runs without waiting on the analytics consent banner and is
described separately on the privacy page.

## The site assistant

The chat launcher in the corner of every page (`components/assistant/`) talks
to `api/assistant.ts`, a Vercel Edge function that shares the AI Lab's model
key and rate limiter. It is grounded rather than general: `api/_siteContext.ts`
fetches the site's **own prerendered pages** at request time — the home page
always, plus up to three more picked by keyword — and the system prompt tells
it to answer from those and nothing else. So there is no knowledge base to
keep in sync; editing a page edits what the assistant knows.

It refuses to invent prices, clients, timelines or results, which means a real
prospect reaches its limits quickly. That is why WhatsApp sits pinned above the
composer rather than buried in a reply, and why it carries the visitor's last
question across. With no model key configured the endpoint returns 503 and the
panel says so, WhatsApp and the audit link still working.

Rename it in one place: `NAME_EN` / `NAME_AR` in `src/data/assistant.ts`, which
holds every string the widget shows in both languages.
